# پویش زمین

فرانت‌اند فارسی، راست‌چین و واکنش‌گرا برای ثبت پسماند خشک، مشارکت اجتماعی و نصب به‌صورت PWA روی Android و iOS؛ به‌همراه Worker، D1 و اپلیکیشن میدانی Android.

## امکانات
- رابط روشن و تیره با انتخاب پایدار کاربر و پشتیبانی آفلاین PWA
- داشبورد وزن پسماند، تعداد مشارکت‌ها و تنوع دسته‌ها
- ثبت پسماند، سوابق محلی و پیام‌های اجتماعی
- API حساب، پروفایل، سوابق و پیام‌ها با نشست امن یا Bearer token
- اپ Android برای ثبت GPS، پیوست تصویر، جست‌وجوی تصاویر OpenAerialMap و صف آفلاین با WorkManager
- پنل خصوصی شرکت در `/company.html` برای مرور سوابق میدانی

## میزبانی و API
- Cloudflare Pages پروژهٔ استاتیک را از پوشهٔ `public` ارائه می‌کند.
- Worker با `wrangler.jsonc` همان رابط را از Assets ارائه کرده و مسیرهای `/api/*` را پردازش می‌کند.
- CORS فقط مبدأهای مشخص‌شده در Worker را می‌پذیرد؛ این محدودیت را برای دامنه‌های ناشناخته باز نکنید.
- GitHub Pages و میزبانی استاتیک جداگانه، داده‌های محلی را فقط در همان مرورگر/دستگاه نگه می‌دارند.

## D1 و migrationها
- `schema.sql` طرح کامل پایگاه برای ایجاد یک دیتابیس تازه را توصیف می‌کند.
- migrationهای `0001` تا `0004` به‌ترتیب جدول‌های اصلی، سوابق مکانی، ارتفاع تصویربرداری و ستون‌های پروفایل را ایجاد/تکمیل می‌کنند.
- بررسی خواندنی پایگاه متصل در 2026-10-31 نشان داد `location_records` و ستون `capture_height_m` موجودند، اما ستون‌های پروفایل `users` وجود ندارند و جدول تاریخچهٔ migration نیز دیده نشد.
- روی پایگاه فعلی، migrationهای 0001 تا 0003 یا `schema.sql` را دوباره اجرا نکنید. پس از تهیهٔ نسخهٔ پشتیبان، با `PRAGMA table_info(users)` نبودن ستون‌های پروفایل را دوباره تأیید کنید؛ سپس فقط migration 0004 را یک‌بار اجرا کنید:
  ```sh
  npx wrangler d1 execute pooyesh-zamin-db --remote --file=./migrations/0004_user_profile.sql
  ```
- برای دیتابیس تازه، از `schema.sql` یا زنجیرهٔ migrationها استفاده کنید؛ هر دو را پشت سر هم اجرا نکنید.

## Android
پروژه در پوشهٔ `android/` قرار دارد. ساخت APK آزمایشی:
```sh
gradle -p android assembleDebug
```
آدرس HTTPS Worker هنگام ورود در اپ وارد می‌شود. ثبت GPS فقط پس از اقدام کاربر و اعطای مجوز انجام می‌شود؛ ارتفاع GPS گوشی معادل ارتفاع دوربین نیست.

## R2 و دسترسی شرکت — پیش‌نیاز انتشار
- Worker به binding با نام `MEDIA` و bucket خصوصی `pooyesh-zamin-media` نیاز دارد.
- R2 در حساب متصل هنوز فعال نیست؛ تا فعال‌سازی R2 و ساخت bucket، آپلود تصاویر در دسترس نخواهد بود.
- secret با نام `COMPANY_ACCESS_TOKEN` باید پیش از استفاده از پنل شرکت در محیط Worker ثبت شود: `npx wrangler secret put COMPANY_ACCESS_TOKEN`.
- مقدار secret را در کد، مخزن یا گفتگو قرار ندهید.

## اعتبارسنجی و انتشار
Workflowهای GitHub، syntax Worker، تنظیمات Wrangler، اجرای ترتیبی migrationها روی SQLite موقت و ساخت APK آزمایشی را بررسی می‌کنند. هیچ migration عملیاتی، فعال‌سازی R2، ساخت secret یا deploy در این مرحله انجام نشده است. پس از آماده‌سازی منابع Cloudflare و موفقیت CI، Worker را جداگانه deploy و `/api/health` را بررسی کنید.
