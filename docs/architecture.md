# پویش زمین — معماری ثبت و پیگیری بارهای پسماند خشک

## اجزای سامانه

- **برنامه مشترکین:** `public/subscriber.html`؛ ورود مشترک، ثبت نشانی و موقعیت، انتخاب اقلام پسماند و ارسال بار به API مرکزی.
- **پنل مدیریت:** `public/admin.html`؛ مشاهده همه بارها، ارجاع به نیروی گشت، لغو ارجاع، تأیید نهایی و مشاهده سوابق.
- **برنامه نیروی گشت:** `public/patrol.html`؛ نمایش فقط بارهای ارجاع‌شده به همان نیروی گشت و ثبت پذیرش/دریافت.
- **API مرکزی:** Cloudflare Worker با نام `pooyesh-zamin-api`.
- **پایگاه داده:** Cloudflare D1 با نام `pooyesh-zamin-db`.

## نشانی API

`https://pooyesh-zamin-api.game-kazem9877.workers.dev`

## نقش‌ها و محدودیت‌ها

- `admin`: دسترسی به همه بارها، مدیریت ارجاع و کاربران، تاریخچه عملیات.
- `patrol`: فقط مشاهده مأموریت‌های متعلق به خودش؛ امکان پذیرش و ثبت دریافت.
- `subscriber`: فقط ثبت بار؛ هیچ دسترسی به فهرست بارها یا ارجاعات ندارد.

محدودیت نقش‌ها در API سمت سرور اعمال می‌شود و صرفاً به مخفی‌کردن دکمه‌ها در مرورگر متکی نیست.

## وضعیت‌های گردش کار

`submitted → assigned → accepted → collected → completed`

- مدیر می‌تواند ارجاع فعال را لغو کند؛ در این حالت بار دوباره در وضعیت `submitted` قرار می‌گیرد.
- تاریخ و ساعت ارجاع، پذیرش، دریافت و تکمیل در پایگاه داده ثبت می‌شود.
- هر تغییر مهم در `audit_events` نگهداری می‌شود.

## API routes

- `GET /api/health`
- `POST /api/auth/bootstrap` — ساخت نخستین مدیر، فقط یک‌بار و با کلید راه‌اندازی محرمانه.
- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/subscriber/loads`
- `POST /api/admin/import-github-records` — انتقال تکرارنشدنی فایل‌های JSON قدیمی از پوشه `records`.
- `GET /api/admin/loads`
- `GET|POST /api/admin/users`
- `POST /api/admin/loads/:id/assign`
- `PATCH /api/admin/assignments/:id`
- `GET /api/admin/loads/:id/events`
- `GET /api/patrol/assignments`
- `PATCH /api/patrol/assignments/:id`

## راه‌اندازی اولیه

1. نشانی `public/admin.html` را باز کنید.
2. گزینه «راه‌اندازی مدیر اولیه» را انتخاب کنید.
3. کلید راه‌اندازی یک‌بارمصرف را وارد کنید و حساب مدیر را بسازید.
4. از پنل مدیریت، حساب‌های نیروهای گشت و مشترکین را ایجاد کنید.
5. اطلاعات ورود هر گروه را فقط به همان فرد تحویل دهید.

کلید راه‌اندازی و کلید امضای نشست‌ها در Secret bindings سرویس Worker نگهداری می‌شوند و در فایل‌های عمومی مخزن قرار ندارند.

## نگهداری داده‌های قبلی

پایگاه داده پیش از این نیز جدول‌های کاربردی دیگری از جمله `users`، `sessions` و `waste_records` داشتند. برای جلوگیری از تداخل، سامانه جدید از جدول مستقل `app_users` برای نقش‌های پنل استفاده می‌کند. جدول‌های قبلی و داده‌های آن‌ها دست‌نخورده باقی می‌مانند.

## نکته انتشار

GitHub Pages باید از شاخه `main` و پوشه ریشه مخزن منتشر شود. فایل ریشه `index.html` صفحه اصلی را ارائه می‌کند و برنامه‌های مستقل در پوشه `public` قرار دارند.
